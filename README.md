# Why are we here?

I know AI can write code, because I have already tried it. Last year, I used 
an AI assistant to build small [Processing](https://processing.org) demos. 
It worked, but I did not fully understand why. So the question behind 
this course — why are we here — has never felt abstract to me. 
It felt personal the first week.

My answer, in one sentence: I am not learning programming to compete with AI
at writing code. I'm learning it to understand and control the systems behind
my work.

## Processing: a result is not an understanding

The first example is about Processing. I learnt some basic Processing knowledge
three years ago, so I can understand some code, but my knowledge is still very 
limited. Last year, I designed a function that used the laptop camera to detect 
the user's posture and alert them when their posture was unhealthy. Those Processing 
demos worked. I typed what I wanted in plain language, received the code, and pressed Run.

The trouble started whenever I tried to fix the code because it didn't work like I expected.
The posture feedback was also inaccurate at the beginning. I wanted to check the code but 
I didn't understand how it actually worked. Most of the time I spent talking to AI to fix the code
because I could only recognize some of the visual part, like the color part.
It took me a lot of time to get it working properly. After that, I edited the visual part by myself
to make it look better.

That is the distinction I keep coming back to: getting a result and
understanding a result are not the same thing. Obviously, the AI tools 
get smarter and more powerful with the development of technology. But 
if I don't study programming, I will never fully understand how it works.

## TouchDesigner: it can be better with coding

The second example is about [TouchDesigner](https://derivative.ca). Its node-based system 
lets me build visual work with almost no code. This system is simple and, honestly, 
enough for most of my basic ideas.

But every time I wanted something more complex, like an interaction where several
parts respond to each other, I ran into the edge of my coding knowledge. 
This year I finished a work called *Diffusion* as my undergraduate graduation project.
I used some TOPs and CHOPs in TD to create the video part. It looked great, but it 
lacked a more interesting interactive component. I knew that TD could do much more with coding, 
but I did not know what was possible or how to achieve it. This was frustrating. 
My work kept stopping at what the software allowed, rather than at what
I wanted to make.

Over the past few years, I have already created several works with TD. I used to use 
photos and videos as inputs and change their parameters in TD. If I could learn more 
about coding, understand how it works, and write some code myself, I believe that
I could create more fascinating work.

## Describing is not specifying

Everyone can talk to AI and ask it to do something, such as developing an idea or creating a picture.
I have learnt that programming instructions must be precise if I want 
a computer to produce the result I expect. For instance, I want to draw an apple by programming.
If I just say,"Draw an apple," the result could be a red, green, or yellow apple. 
However, if I want to create an apple that looks the way I expect, I need to specify its position, 
size, color values, outline thickness, and the coordinates of its stem and leaf. 
These parameters turn a visual idea into instructions that a computer can execute.
This idea also connects with Beattie’s discussion of code as a creative medium(Beattie, 2019).

## What I still need, if AI keeps improving

AI will keep getting better at writing code. As a student in design school, I 
didn't expect that to write code as quickly or as well as AI. After this class, 
I just hope that I would never be afraid of seeing so many lines of coding language,
and have the ability to create some work by myself. AI can also make mistakes, 
as I have experienced when using AI tools. AI can even get simple calculations wrong, 
so I still need to check its output myself. Therefore, basic skills such as reading, 
understanding, and modifying code are still important for me to learn and practice.

## What I wanna do in the future

There is an artist called *Yoshi Sodeoka* whose work I have admired since my undergraduate years.
In his work, I could see that digital video, generative processes, and mathematical structures 
create visual experiences that move between order and chaos. His work *Migratory Parameters* (2025) 
is an example of the kind of digital visual experience that interests me. In the video I saw the migratory 
paths of birds in the sky and their movements transformed into a complex digital visual experience.
I'm interested in how real-world behaviour can become an artistic visual system through computation.

This connects with my experience using TD. I can already change parameters to create interesting 
visuals, but I want to create more works based on real-world data and behaviours. If I learn programming, 
I hope I can move beyond adjusting existing effects and start designing the systems behind them. 
For me, this is one reason to learn programming: not just to make code work, but to understand 
how a set of rules can become an artistic experience.

## Where I land

I'm here not because I need to write code faster than AI, but because I want to
understand the medium I work with. I want to move beyond using software only 
through its existing tools and parameters, and become more confident in designing the systems behind my ideas.

AI may continue to write more code for me in the future. I don't know exactly what 
programming skills will still be necessary by the time I graduate or start my career.
But I know that I want to be able to understand what I am making, make decisions about how it behaves, 
and keep exploring possibilities beyond what I already know.
